You changed

What you do

  1. Raise current_version in the notebook's top cell, for example from 1.0.0 to 1.0.1.
  2. Run the notebook's bottom cell again, so that requirements.yaml matches the new version.
  3. Upload the notebook through the form, with exactly the same file name as the one in your repository, and merge the pull request.

What the workflow then does

  • Reads each notebook's current_version into notebooks/notebook_latest_versions.yaml and updates the changelog.
  • Hides the code cells and refreshes the notebook index.
  • When a requirements file changed: merges the requirements, tests them in a conda environment and commits the results if the test passes.

What you do

Merge the change to the code in src. No version number needs to be raised.

What the workflow then does

It writes the time of the change to .tools/meta/src_change.yaml. The installed app compares that time with its own copy.

Publish a release with a new tag. A workflow raises the version in construct.yaml to the tag and builds new installers.
