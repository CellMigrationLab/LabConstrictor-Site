Check the Actions tab first. If a workflow is running, wait until it finishes: starting a release while other jobs run may cause build conflicts.

The tag must follow semantic versioning: MAJOR.MINOR.PATCH, for example 1.0.0 or 1.2.3. A description is optional.

Publish release

Publishing starts the workflow Build Release Installers, which creates the installer files for your notebooks. Follow it in the Actions tab; the workflow-status guide shows how to read a failure.

Release assets (an illustration)

  • MyApp-0.0.1-Windows-x86_64.exe
  • MyApp-0.0.1-MacOSX-arm64.pkg
  • MyApp-0.0.1-MacOSX-x86_64.pkg
  • MyApp-0.0.1-Linux-x86_64.sh

When the workflow completes, open the release and download the installers from its Assets list. The App Centre page of an app links straight to these files. Two more workflows run when you change notebooks or code, and a weekly one can keep your repository in step with the template.
