# Implementation plan (user-supplied): interactive microscopy demo at /demo/ (NucleiSky 2D registration)

Status: SPEC supplied by the user, to be feasibility-checked and merged into the final plan. Not yet verified against the repos.

## Objective
Realistic interactive demo at `/demo/` showing how a LabConstrictor-packaged microscopy analysis is reached through (1) a JupyterLab notebook, (2) a napari plugin (experimental), (3) a Fiji plugin (experimental). All three show the SAME scientific task, SAME example data, consistent results. Runs entirely in the browser: static HTML/CSS/JS and precomputed outputs; no Python, kernel, Fiji, napari, account, upload or backend. Visual fidelity is a primary requirement: reproduce layout, colours, controls, names, proportions from the real screenshots; not a generic dashboard mockup. Work in CellMigrationLab/LabConstrictor-Site on a feature branch; do not modify other repos or push to main.

README.md, AGENTS.md, DESIGN.md, scripts/build_site.py, scripts/lcsite/config.py, page.py, pages_site.py, scripts/check_site.py, check_design.py, mkdocs.yml, docs/assets/stylesheets/lc.css, docs/assets/javascripts/lc.js. ## 2. Scientific example: NucleiSky 2D registration
Locate a small, possibly rotated and rescaled image within a larger reference using positions of nuclei. Visitor sees: large fluorescence reference; smaller query at different magnification; the parameters; a simulated run; query located and aligned; a microscopy overlay.
Sources: NucleiSky repo; notebooks/NucleiSky2DApp/NucleiSky2DApp.ipynb; app/menuinst/Welcome.ipynb; docs/assets/2D_QC.jpg (representative output); deterministic synthetic fixture LabConstrictor-Tools/fixtures/make_nucleisky.py (generates a large reference image, a smaller query, a JSON with the known transformation). Prefer generating reference and query from this fixture, render and optimise once into static assets, generate an overlay from the documented ground-truth transform. Do not recompute NucleiSky in the browser. Do not combine an input from one dataset with a result from another as one analysis; if the QC image is used, say it is a separate illustrative result.
Fixture values claimed: reference 1600x1600 px, query 520x520 px, reference pixel 0.65 um/px, query 0.325 um/px, rotation 12 degrees, twofold sampling difference. Keep displayed values consistent with the chosen fixture/validated output. No invented measurements, accuracy, confidence, durations. State clearly that the registration output is PRECOMPUTED.

## 4. Interaction design
Three views: Notebook | napari | Fiji, switchable any time. Description above: "Explore how the same NucleiSky microscopy workflow appears in a notebook, napari and Fiji." Host views visibly labelled "Experimental integration preview".
Notebook: initial Welcome open, NucleiSky notebooks listed, NucleiSky2DApp has "Open the notebook". On activation: simulated NucleiSky2DApp.ipynb tab, reference + query sample images, representative controls, "Run matching". After Run: precomputed result, overlay, short explanation, inspectable. Working Show/hide code control revealing a short representative code cell.
napari: initial reference and query layers, NucleiSky and Relocalize 2D selected, parameters visible, no output layers. After Run: aligned layer, output entries in layer list, neutral status message identifying an EXAMPLE result, toggle layer visibility, adjust overlay opacity.
Fiji: initial reference/query visible, tool dialog open, prefilled parameters. After OK: dialog hidden/completed, overlay shown; can return to settings and repeat.
Shared small deterministic state: active interface, current step, whether result visible, selected/visible layers, overlay opacity, code visibility, advanced settings expansion. Changing interface must not change the data or transformation. "Reset demo". Only meaningful controls (opacity really changes the picture; toggles really hide). If threshold/matcher parameters are not recomputed, show recorded example values; do NOT fabricate new results when a control changes.

## 5. Architecture explainer
One collapsible "How the connection works": 1 app installed on the user's computer; 2 installer registers the application; 3 LabConstrictor-Tools exposes declared scientific functions; 4 napari or Fiji generates its own UI from those declarations; 5 the tool runs in the app's own Python environment in a separate worker process; 6 outputs return to the host as images, layers, overlays, points or tables. Link to LabConstrictor-Tools. State that the website does not connect to a local Fiji or napari.

## 6. Experimental status
Bridge under development; repos report Linux testing with actual applications; Windows and macOS insufficiently tested. NucleiSky's public labconstrictor-app.yaml advertises notebook support only. So: do not modify NucleiSky's host declaration; do not describe napari/Fiji integrations as stable; no production-ready compatibility badges on its App Centre listing; label both host views experimental previews; link to the installation guides (LabConstrictor-Tools, napari-labconstrictor, LabConstrictor-Fiji docs/user-guide.md) as the authority.
